# dlz-remake

《抗日：地雷战》（西山居，1998，Win32/DirectDraw，MSVC 5.0）的复刻工程。

原版素材放在 `../dlz/ANTI-JAP/`（约 936 MB，只读），本目录只放代码与抽取产物。
当前离“完整可玩 + 原汁原味”的差距、优先级与验收标准见 **[GAPS.md](GAPS.md)**。

## M1 单关试玩（Godot 4.7.2）

**M1 完成**：`godot/` 工程可玩 **L14 地道战**（5 我方 / 13 敌军，默认）与
**L08 救援白洋淀**（4 / 16）。含双方单位、地形移动消耗、普通攻击、地雷埋设/引爆、

## 已确认格式

### IMG（位图，86 个 / 17.0 MB）

```
0x00  4B   'IMGV'
0x04  2B   pad (=1)
0x06  2B   宽 - 1 (LE)
0x08  2B   高 - 1 (LE)
0x0A  6B   pad
0x10  w*h  8bpp 索引像素，逐行、自上而下、无压缩
随后  768B 调色板，256 × RGB，每分量 6 位（×4 → 0-255）
```

校验：`16 + w*h + 768 == 文件长度`，84 个文件成立。

调色板细节：83 个文件是 6 位分量（0..63，×4）；`DLZ00.IMG` 是唯一的 8 位分量
（0..255，不再放大）；`BUTTON00/01.IMG` 尾部 768 B 全 0，是发行版里的空占位
（对应 `button00.tga`/`button01.tga` 另有文件）。

两个像素尺寸异类：

| 文件 | 头部声明 | 实际像素 | 判定依据 |
|---|---|---|---|
| `END04.IMG` | 640×480 | **320×200** | 像素区 64,000 B；`16+320*200+768 = 64,784` 正好等于文件长度；按 320×200 解码是完整结局图（两人背影） |
| `ZYB.IMG` | 640×480 | **640×7,562** | 像素区 4,839,680 B = 640×7,562；`16+640*7562+768 = 4,840,464`；第 5/6 屏交界处「袁世辉」三字上下半截正好接上 → 纵向滚动字幕长图 |

2005 年轩辕春秋帖称「像素从下到上逆序存放」，本机渲染 `MINE01`/`BIGMAP` 时文字正立，已否证。

### TXT.DAT（剧情文本，110,900 B）

整文件逐字节 XOR `0x51` 后即 GB18030 文本；记录 = `三位编号` + 若干行（行首 `-1`）+ `xx` 终止。
共 **478 条、55,005 字**。`GG`/`BB`/`TT`/`AA` 是运行时替换的占位符（人名/地名）。

### PEOPLE.DAT（40 × 132 B）

```
0x00 char[16]  name       GBK，如「张　嘎」
0x10 u32       face       头像索引 → FACE.DAT 170 张
0x14 u32       pad2
0x18 u32       unknown    实测 0/1/2；模板称 enemy，但日军/伪军也为 1，未采信
0x1C u32       wuli       武力
0x20 u32       zhili      智力
0x24 u32       level      等级 1..60
0x28 u32       jingyan    经验（本机全 0，运行时字段）
0x2C u32       bingzhong  兵种 → GAME.DAT BingZhong[96]
0x30 u32       gongji     攻击（技能）
0x34 u32[16]   技能等级    buji/jili/yiliao/…/kongxi，顺序同 GAME.DAT JiNeng[16]
0x74 u8[8]     wupin      携带物品 → WuPin[160]
0x7C u8[8]     dilei      携带地雷 → DiLei[10]
```

校验：`5,280 = 40 × 132`；40 个名字全为合法 GBK；`face ∈ 0..169`；`bingzhong ∈ 0..89`；
`wupin`/`dilei` 取值均落在 GAME.DAT 的表长内。

| `0x725C` | 480 | **DiLei 地雷** | 10 × 48 |

### FIGHT.DAT（47 × 20,508 B）

```
0x0000   700 B    Intro：关卡名 / 难度 / 胜负文本 / 宝箱 / 特殊位置
0x02BC  8192 B    Fighter[128] × 64 B
0x22BC 11616 B    People[88] × 132 B（与 PEOPLE.DAT 同构）
```

Intro（700 B 全部有着落）：

```
0x000  char[32]  name
0x020  u32       difficulty_raw（模板称难度，未独立验证）
0x024  u32       fight_txt_raw（模板称对话索引，未独立验证）
0x028  char[64]  success
0x068  char[64]  failure
0x0A8  Chest[4] × 28 B：x, y, appearance, wupin, wupin0, wupin1, wupin2
0x118  u32       special_count_raw（多数关卡等于特殊位置数；0/999 例外）
0x11C  u8[32]    未解析
0x13C  Special[32] × 12 B：x, y, type（0..3）
```

Fighter 槽位（强验证）：

- `Fighter[0..39]` ↔ `PEOPLE.DAT[0..39]`（40 个有名角色）
- `Fighter[40..127]` ↔ `People[0..87]`（每关 88 个战场名册）

Fighter 64 B：

```
0x00 pad0(0)   0x04 tili       0x08/0x0C/0x10 恒 100
0x14 pos_x     0x18 pos_y      0x1C direction(0..3)
0x20 dest_x    0x24 dest_y     0x28 dest_direction（初始 == x/y/dir）
0x2C target_slot 0x30 target_x 0x34 target_y
0x38 pad38(-1) 0x3C stage(1=出场) 0x3D behavior 0x3E pad3e 0x3F moveable
```

校验：
- 47 关共 **1,377 个出场单位**；坐标全部落在对应地图尺寸内。
- 29 个出场的有名角色中，28 个 `tili == unit.tili + (level-1)*tili_plus`；
  孙悟空固定 80 HP（彩蛋特例）。
- `FIGHT.People` 槽（40..127）的 `tili == 4500` 共 **3,807 次**（其中 1,052 条 stage=1），
  极可能是“HP 未显式设置”的哨兵，不能直接当成 4500 血；只有 96/80/1376/212 等
  少数显式值可直接用，M1 需从战斗初始化代码确认。
- **102 个有效宝箱、440 个地图内特殊位置**。

⚠️ `People[88]` 是每关战场名册（伪军/日军/碉堡/维持会…，空位填「孙悟空」），
不是 `PEOPLE.DAT` 的拷贝。

### TOWN.DAT（19 × 346 B）

`346 = 81 × u32 + 11 × u16`。前 35 个 int32：

```
0x00 pad0(0) / pad1(-1)
0x08 3 × (wave, x, y)    环境音热点；wave 落在 WAVE.DAT 的 800 段
0x2C building_label_x[6]
0x44 building_label_y[6]
0x5C building_offset_x[6]
0x74 building_offset_y[6]
```

商品切片（`raw_u32` 下标）：

| 字段 | 切片 | 长度 | 校验 |
|---|---|---|---|
| `goods_what` | 35..44 | 10 | 19 个城镇全为 -1（代码未使用） |
| `goods_junxie` | 45..56 | 12 | 取值 81..142，落在 WuPin 武器区 |
| `goods_zahuo` | 57..68 | 12 | 取值 1..80，落在 WuPin 食物/书籍区 |
| `goods_material` | 69..80 | 12 | 取值 0..9，正好是 Material[10] 索引 |
| `flags` | +324 | 11 × u16 | — |

6 个建筑槽的候选顺序是 民房/指挥部/军械部/杂货铺/出口/作坊；
本机只能证明槽位数、坐标值域和「小城镇只启用部分槽位」，顺序未独立验证。

19 个城镇名来自 `DLZ.exe` 0x045058 起的 GBK 串，顺序与 TOWN/PLACE 记录一致，
并已用 PLACE 背景里烧进画面的地名逐条比对：
桃花岭 / 赵村 / 花坪镇 / 李村 / 土桥 / 白洋淀 / 萧家庄 / 冉庄 / 枣庄 / 阳村 /
清风寨 / 鸡公山 / 太平镇 / 黑风寨 / 长湾 / 施南镇 / 红岩镇 / 平阳县 / 天池山。

### MAP.DAT（120,690 B）

```
0x0000  512 B   Index[64] × (u32 offset, u32 length)
0x0200  ...     Data[47]：
                u16 width, u16 height
                char blk_name[12]   "dlz-11.blk"
                char pal_name[12]   "dlz-01.pal"
                u16 tiles[width*height]
```

关键：**Index 的 offset 相对 Data 区（0x200）**，不是文件绝对偏移。
47 张图 `length == 28 + width*height*2`，首尾相接铺满 120,178 B；
第 47..63 个索引槽为 `(120178, 0)`。

tile 值：高 4 位地形号，低 12 位 = BLK 套内索引；47 张图的低 12 位全部小于对应套的 tile 数。

### BLK.DAT（15,805,952 B）

```
0x0000  512 B   Index[64] × (u32 offset, u32 length)，前 16 个有效
0x0200  ...     Data：16 套 48×48×1 B tile
```

- 每 tile 2,304 B，8bpp 索引。
- 7 套各 512 tiles、7 套各 468 tiles、2 套为空（`dlz-08` / `dlz-10`）。
- 共 6,860 tiles，Data 区 15,805,440 B。

渲染用 IMG 的通用调色板（29 个 IMG 共用的那一组）。原版目录没有 `*.pal` 文件，
EXE 里也没有 `dlz-01.pal` 字面量；地图用通用调色板渲染后地形/树林/房屋/铁路均连贯。

### FACE / ARMY / MINE / FLM / GOODS / MATERIAL / PLACE

| 文件 | 单帧 | 数量 | 结构 |
|---|---|---|---|
| `FACE.DAT` | 80×100 | 170 | 纯 8bpp，1,360,000 = 170×8000 |
| `ARMY.DAT` | 48×48 | 91×19 = 1729 | 每兵种 19 帧，3,983,616 B |
| `MINE.DAT` | 48×48 | 10×4 = 40 | 每雷 4 帧，92,160 B |
| `FLM.DAT` | 48×48 | 32×16 = 512 | 每动画 16 帧，1,179,648 B |
| `GOODS.DAT` | 48×48 | 128 | 物品图标；`WuPin.goods` 直接是 0..127 索引 |
| `MATERIAL.DAT` | 48×48 | 10 | 材料图标，与 Material[10] 一一对应 |
| `PLACE.DAT` | 640×480 | 19 | 每条尾部 1024 B = 256 × RGBA 调色板 |

前 6 个用 IMG 通用调色板；ARMY/MINE/FLM/GOODS/MATERIAL 的索引 0 按透明色导出。

### WAVE.DAT（12,992,170 B）

```
0x0000  8,192 B   Index[1024] × (u32 offset, u32 length)
0x2000  ...       PCM：22050 Hz / 单声道 / 16 bit signed LE
```

- 1024 项里 152 项有效；其余为 0 长度占位，表尾 1001..1023 为全零。
- 所有项首尾相接，`sum(length) == 12,983,978`；总时长约 **294.4 秒**。
- 索引号就是游戏音效 ID；GAME 的 `audio_gongji`/`audio_yidong` 与 TOWN 的 803/808/812 都直接引用它。

## 彩蛋线索

- **隐藏关（EXE 静态证据）**：`DLZ.exe` 的 `0x40EC40` 比较一个全局分数与 **2800**，
  ≥2800 时在 `0x40EC6E` 弹出「由于GG的优良表现，可以进入隐藏关，请选择隐藏关的模式。」
  菜单两项为 **模  拟 / 虚  构**（`0x446EC/0x446F4`）。2800 之前统一走 `jz-1.img`。
- **多结局阈值**：同一全局值还有 3000/3300/3600 三档；结局图 `end00`–`end05`、
  `jz-1/jz-2`，加载代码在 `0x40E700–0x40EA00`。
- **孙悟空**：`PEOPLE.DAT` 第 0 条就是「孙悟空」（face 0、武力/智力 99、兵种 0），
  `GAME.DAT` 的 `zhuanzhi = -1` 表示「不可转职」；`zhuanzhi = 0` 只出现在
  90–95 号空兵种，不能当作“孙悟空哨兵”（此前说法已用本机字段否证）；
  `FIGHT.DAT` 每关 88 个 `People` 槽位里的空位也全部填「孙悟空」。
- **神仙队**：`GAME.DAT` 兵种第 0 条「神仙队」是作弊单位（体力 1000、攻/防 500、选择范围 6、应用范围 9）。
- **恶搞关**：第 44 关「中国象棋」（击毙冈村宁次）、第 45 关「龟兔赛跑」（柳忻 vs 龟田），
  第 46 关「鬼子进村」。
- **孙悟空的 HP 特例**：第 14 关「地道战」里他作为有名角色出场，HP 固定 80，不套兵种公式。
- **4500 是哨兵，不是 BOSS**：第 1 关槽 47 的 4500 与大量空槽同值；同关槽 45 的 1376
  才是显式值。全表 3,807 条 4500，直接当 HP 会做出 1,052 个“4500 血杂兵”。
- **动物/梗头像**：`FACE.DAT` 里有狗、蒙面忍者、相扑手、白胡子老头等非普通角色头像。
- **金币/价格梗**：蟠桃价格 10000、`para1=5000`；物品里还有核弹、人参、电池、外星植物等图标。

复刻里可以把「孙悟空」做成主菜单隐藏入口：标题界面输入特定按键 → 解锁「孙悟空 / 神仙队」试玩关。
**M5 已完成，这条列为后续彩蛋精修；不影响三关/战役主线。**

## 用法

```bash
python3 extract_all.py     # → out/img、out/map、out/face…、out/wave、data/*.json
python3 verify.py          # 17,453 条断言，逐条校验格式结论与产物
./run_game.sh              # → M1-M6 数据/UI/剧情/字库，打开完整游戏
./verify_all.sh            # M1-M6 全量无头回归
./run_m1.sh                # M1 纵切
./run_m2.sh                # 兼容入口：等同 run_game.sh
./verify_m3.sh             # M3 原味 UI
./verify_m4.sh             # M4 47 关
./verify_m5.sh             # M5 剧情/结局
./verify_m6.sh             # M6 战斗系统
./verify_play.sh           # M7 47/47 + M8 36/36（较慢）
python3 tools/prepare_m5_media.py   # 首次/需要时：MPEG/FLC/ANM → godot/assets/m5
```

产物：

```
data/   17 个 JSON：txt/people/game/fight/fighter/town/map/blk/face/army/
        mine/flm/goods/material/place/wave/sprites
out/    img 86、map 47、face 170、army 91、mine 10、flm 32、goods 128、
        material 10、place 19、wave 152、blk 14、atlas 7
```

`data/` 与 `out/` 都是生成物，不入库（体积 + 版权）；原版资源目录只读。

M0 图文报告（地图图集、数据表、彩蛋清单）在 `../dlz-m0-report/`，**不在本仓库内**；
入口：`../dlz-m0-report/index.html` 或 `../dlz-m0-report/M0_REPORT.md`。

M1-M6 工程：`godot/`（项目/场景/脚本/无头测试）；运行说明见 [godot/README.md](godot/README.md)。
原版 UI/关卡/剧情管线：`tools/prepare_m3.py`、`prepare_m4.py`、`prepare_m5.py`、
`prepare_m5_media.py`；校验：`verify_all.sh`。
